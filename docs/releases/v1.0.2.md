# agent-tool v1.0.2

## Quick Start
1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in file tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in file tools when available.

## What's New

Debug types now reach the agent where it looks for them. Decompiled code used to name
`Node *`, `MODE_AUTO` or a masked bitfield with no way to look the type up, and only
decompile accepted symbol names.

### decompile

- The structs, unions and enums a function's C names follow it: members with offsets
  (`+0x24 Flags flags;`), bitfield bit ranges, base classes, enum values in hex and decimal.
  An enum is also found through an enumerator the code compares against, and enums of shown
  members come along. A class with hundreds of members shows the ones the function uses
  (`1 of 489 members`). Bounded to 6000 characters per function.
- Bitfield constant stores compiled as `& ~clear | set` print as `p->mode = 5` instead of masks
  (Gosleigh v0.1.6; Ghidra 12.1 keeps the masks here).
- `va` names resolve by scope suffix (`Rect::area` or `area` for `geo::Rect::area`); a name
  several functions share is an error listing each address; typos get suggestions.
- Output past `max_output_chars` continues with `result_offset`.

### type_info (new operation)

- `analyze(operation="type_info", type_name="Player, EState")`: PDB or DWARF definitions by
  qualified name, by the name decompile prints, or ignoring case. Union alternatives a
  decompiled layout cannot hold are listed and marked.

### Symbol names everywhere

- disassemble, function_at, call_graph, xref `target_va`, follow_ptr, rtti_dump, struct_layout
  and hexdump take function, global and import names (`name+0x10` for an offset).

### struct_layout

- Lays the debug type over image memory: the global at `va`, or `type_name` over any address,
  member by member with values (nested paths, bitfields, enum names, annotated pointers,
  strings; zero-filled aggregates folded). Untyped memory keeps the pointer-sized slots.

### xref field

- The class as decompile prints it (`Rect::w_` for `geo::Rect`).
- Offsets below 0x80 (a one-byte displacement, which a byte search cannot find) decode the
  whole binary instead of scanning only the class's methods; methods and functions whose
  prototype takes the class are decompiled first. Previously a free function such as
  `use_node(Node *n)` was never a candidate.
- MinGW/Go PE images use their DWARF, and functions are named from it.

### DWARF

- `typedef struct { ... } Obj` and `typedef enum { ... } Mode` print as `Obj` / `Mode` instead
  of `anon_N`.

### Performance

- PDB name indexes reuse the type table's existing definition scan (gopdb v0.1.3). On a 78 MB
  x64 image with a 370 MB PDB: type_info 2.2 s first call, then instant; the type section adds
  about 0.1 s per decompiled function.
- Debug info for type_info, struct_layout and name lookup is cached between calls.
